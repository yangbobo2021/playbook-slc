# 复验边界

## 时间与信息收益

诊断先用已有失败记录、各次产物快照和离线源码，仓库测试禁止启动真实 SLC/Agent。一次完整编译可能耗时几十分钟，不能用“再跑一次看看”代替假设。

真正复验前写清要验证的假设、最小阶段、预期信息、时间预算和日志位置。无历史耗时默认总预算 5 分钟，用户预算优先；若已有记录显示正常耗时超过预算，提供手动命令或采用更小的验证，不重复启动注定超时的全链路。执行期间保留过程输出，超时中止须处理该次子进程，不能影响其他会话；报告超时而非产品失败。不要无期限等待“still running”。相同错误无新证据时停止。

## 补丁检查

将修改前的目标文件按补丁路径放入临时副本。已完成修改时，用备份中的原始字节准备副本。优先从修改前后的文件生成 diff，避免手写分块行数。保存最终补丁文件，从对应的副本根目录执行 `git apply --check -- /absolute/path/to/suggested.diff`。临时副本无需初始化 Git 仓库。

记录基准文件版本、执行目录和检查结果。遇到格式、路径或上下文错误时，重新生成或修正补丁后再查。内联展示时使用已检查的内容，保持路径、上下文、分块行数和末尾换行。缺少匹配的原始文件或可用 Git 时，说明未验证原因。

退出码 0 证明补丁可应用到该副本。将这个结果与 SLC 编译、Playbook 加载和实际执行业务的结果分别记录。纯诊断和文字建议无需制作补丁。

## 按修改对象复验

先读本版 CLI 帮助及审计中的实际检查命令。使用 argv 数组或正确引用，不能把用户路径或日志直接拼成 Shell 代码。

| 修改对象 | 复验起点 | 不成立的推断 |
| --- | --- | --- |
| 自然语言 | 原真实入口和配置的完整 slc playbook SOURCE | 旧 FSM 的 playbook.link 不读取新描述 |
| GEARS | 从本版支持的后续阶段编译并重新链接 | 旧入口不会自动代表新结果 |
| FSM | 本版供应的 slc check fsm 或等效检查，再重建后续 | TS 通过不等于覆盖检查通过 |
| 链接模块 | 本版 link 检查和正常构建路径 | 手改 manifest/pin/哈希不是验证 |
| 环境依赖 | 环境验证后用相同输入重试 | 新版本通过不是旧版本已修复 |

若增量机制会覆盖补丁或拒绝陈旧构建，保留补丁及产物，在独立复验目录使用本版支持的阶段方式。不能确定如何生成有效入口时，只报告“阶段通过，最终构建未验证”，不直接运行旧 mjs 绕过检查。

保留 argv、cwd、输入哈希、起止时间、退出码、stdout/stderr、接受输出和最终 manifest。结合本版结构化结果判断，不只搜 verified/wrote。阶段通过不是整体通过，FSM 存在不是可执行入口。

导入、构造、接收首轮输入和完整业务执行分别记录。导入也可能有副作用，未经要求不执行用户生成模块。最小启动先查入口和初始化行为，使用隔离数据，说明是否真实调用 Agent。未运行业务不得声称质量提升。

不关闭检查器、不把失败当成功、不伪造业务输出。用户允许放宽流程时可以调整行为，但原输入失败仍需保留。
